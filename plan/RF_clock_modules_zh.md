# RF-clock 设计计划：5.8 GHz 双向时间传递驯服 FS725

> 本文是 `plan/RF_clock_modules.md`（英文，标准版）的中文翻译，两者内容一致。

> 本文档是重新设计的版本，不继承以前 H00-H19 的模块划分和已有 RTL。原则：**算法在 ARM；PL 负责确定性的时间和每个突发的测量链路**——维护 raw tick、在确定的 tick 发射和采集、给样本块打时间锚点；又因为两个节点在 2 ms 乒乓的突发里交换测量值（§5），PL 还负责突发成形、窗口相关和测量包的收发。

## 1. 目标

两个节点 A（主）和 B（从），各有一台 SRS FS725 铷钟和一块 RFSoC 板。目标是**修正 B 的 FS725，使 B 的 10 MHz 和 1PPS 跟随 A**：

- 10 MHz：B 与 A 同频（syntonization）；
- 1PPS：B 的 PPS 沿与 A 的 PPS 沿对齐（time synchronization）。

测量手段是 5.8 GHz 无线双向时间传递（two-way time transfer, TWTT）：A、B 互相发送已知 PRN 突发，各自测量对方突发的到达时间，两个方向相减即可消去传播延时，得到钟差。

## 2. 系统结构

~~~text
 节点 A（主）                                         节点 B（从）
 FS725_A                                              FS725_B  <── RS-232 修正 ──┐
  │10 MHz   │1PPS                                     │10 MHz   │1PPS              │
  v         v                                         v         v                  │
 板上时钟链  PL: PPS 捕获                             板上时钟链  PL: PPS 捕获      │
  │(LMK/LMX)                                          │                            │
  v                                                   v                            │
 RFDC DAC ─ BPF ─ PA ─ TX天线 ~~~~ 5.8 GHz ~~~~> RX天线 ─ LNA ─ BPF ─ RFDC ADC     │
 RFDC ADC ─ BPF ─ LNA ─ RX天线 <~~~ 5.8 GHz ~~~~ TX天线 ─ PA ─ BPF ─ RFDC DAC     │
  │                                                   │                            │
 ARM_A: 监控 ─────── 测量值随突发传送（不经网络）──────── ARM_B: TWTT/Kalman ─────┘
~~~

关键前提：**每块 RFSoC 的 DAC/ADC 采样时钟、PL fabric 时钟和 raw tick 全部由本节点 FS725 的 10 MHz 经板上 PLL 派生**。这样 raw tick 就是 FS725 的时间刻度；调整 FS725_B，节点 B 的整个时间基准随之移动，环路闭合。

### 2.1 职责划分

| 职责 | ARM（Python 为主） | PL |
| --- | --- | --- |

| 时隙规划：周期、角色、偏移、预期延时 | 配置 | 每个时隙执行（时隙引擎） |
| 码片流 → RRC FIR → DAC，从时隙开始 tick 起连续输出 | 否 | 是 |
| 在时隙的 tick 开始 RX 窗口 | 否 | 是 |
| 相关、峰值质量、亚采样延时、载波相位 | 只用于捕获和核对 | 每个窗口跟踪；失锁或请求时整窗搜索 |
| 测量包：组装、扩频、解扩、CRC | 捕获阶段解码 | 是 |
| 在 DDR 里的长窗口上做捕获 | 是 | 采集窗口 |
| TWTT 计算、Kalman 滤波、FS725 修正 | 是 | 否 |
| raw tick 计数、PPS 捕获 | 否 | 是 |

## 3. 射频频率规划（RFDC IP 已接受；板上待验证）

| 项目 | 取值 | 说明 |
| --- | --- | --- |
| 载波 | 5.8 GHz | 5.725–5.875 GHz ISM 频段中心，带宽约 150 MHz |
| RFDC 参考时钟 | 480 MHz | ADC tile 0/2、DAC tile 0/2 各自的参考时钟，由 LMK/LMX 从 FS725 10 MHz 派生 |
| DAC 采样率 | 9.6 GS/s | DAC tile 2 通道 0（`vout20`）；IMR 高通数据通路，插值 ×6 再 ×2（共 ×12），NCO 3.8 GHz，mix-mode。5.8 GHz 是第二 Nyquist 区（4.8–9.6 GHz）里 3.8 GHz 的镜像，约在 0.604 fs；3.8 GHz 分量由 TX BPF 抑制 |
| ADC 采样率 | 4.8 GS/s | ADC tile 2 通道 0（`vin2_01`）；5.8 GHz 欠采样，位于第三 Nyquist 区（4.8–7.2 GHz），折叠到 1.0 GHz，NCO −1.0 GHz 混到基带；RX BPF 必须抑制会折叠进来的带外信号 |
| 复基带采样率 Fs | 800 MS/s | DAC 插值 ×12、ADC 抽取 ×6 |
| PRN 码片率 | 100 Mchip/s | 每码片 8 个样本，一个码片正好一个 tick |
| RRC 滚降 β | 0.25 | 占用带宽 100 × 1.25 = 125 MHz，留在 ISM 频段内 |
| fabric / raw tick 时钟 | 100 MHz | 每 tick 正好 8 个复样本；tick = 10 ns |
| AXIS 位宽 | 256 bit | 8 × (16-bit I + 16-bit Q)，DAC 和 ADC 相同 |

上述所有频率都是 10 MHz 的整数倍，保证"样本编号 ↔ raw tick"是精确的整数关系。

**MTS 对 tile 的要求：** 延时确定性需要 RFDC 的 MTS。RFDC 2.6（Vivado 2024.1）只有在同类至少两个 tile 参加、且每个参加的 tile 都启用通道 0 时才允许 MTS。4x2 板上引出的是 ADC/DAC 的 tile 0 和 tile 2，两者都有自己的参考时钟，所以 tile 0 以相同配置、各自的 PLL 参加 MTS，数据不用；不使用片上时钟分发（参与分发的 DAC tile 采样率上限为 7.0 GS/s）。依据见 `plan/checklist_zh.md` §1、§3。

**频谱翻转：** 5.8 GHz 是第二 Nyquist 区镜像，发射的 RF 频谱相对基带是翻转的；ADC 在第三（奇数）Nyquist 区，不翻转。所以接收基带是发射基带的共轭。BPSK PRN 经实系数 RRC 后是实信号，共轭不影响；若以后换成复数波形，相关模板要取共轭。
### 3.1 RRC 脉冲成形参数（PL 中的 FIR，系数由 ARM 提供）

| 参数 | 值 | 说明 |
| --- | --- | --- |
| `RRC_CONFIG_ID` | 2134958710 | 滤波器的标识：RRC 参数的哈希，系数在运行时现算（`rrc_config()`） |
| `RRC_SAMPLES_PER_SYMBOL` | 8 | 每码片 8 个样本 |
| `RRC_SPAN_CHIPS` | 10 | 滤波器跨度 10 码片 |
| `RRC_TAP_COUNT` | 81 | = 10 × 8 + 1 |
| `RRC_TAIL_SAMPLES` | 73 | = 81 − 8；突发总长 = 码片数 × 8 + 73 |
| `RRC_BETA` | 0.25 | 滚降系数 |

- ARM 计算 float64 系数（`rrc_config()`），量化后写入 PL 的 FIR（P3）；PL 以每码片 8 个样本，把每个突发的码片流（PRN、保护间隔、测量包）成形为 DAC 的 16-bit I/Q；
- 接收端相关使用的本地模板必须由**同一个 config_id** 的波形生成，`config_id` 随每个测量包发送（§5.1），两端不一致时拒绝该测量；
- 发射端只做一次 RRC。接收端第一版直接与"PRN ⊛ RRC"模板做相关（等效于匹配滤波），不再单独做一次接收 RRC。

**必须核实：** ADC 在 5.8 GHz 的输入带宽和性能、DAC 在 0.604 fs 处（mix-mode）的输出功率、板上时钟链能否接受外部 10 MHz。发射功率需满足当地 5.8 GHz ISM 法规。

## 4. 时间模型和 TWTT 方程

### 4.1 本地时间

每个节点的 PL 维护一个从不复位的 64-bit `raw_tick`（100 MHz）。PL 在每个 PPS 沿捕获 `pps_tick[k]`。本地时间以"第 k 秒 + 相对 PPS 的偏移"表示：

~~~text
T_local = k + (tick - pps_tick[k]) * 10 ns + (样本内偏移)
~~~

TX 突发在 `tx_tick` 开始；RX 窗口在 `rx_tick` 开始；PL 相关器得到峰值位置 τ̂（单位：样本，含分数部分）。于是：

~~~text
发射时刻 T_tx = tx_tick 对应的本地时间
到达时刻 T_rx = rx_tick 对应的本地时间 + τ̂ / Fs
~~~

### 4.2 双向方程

定义 θ = T_B − T_A（同一真实时刻下 B 的读数减 A 的读数），δt/δr 为各节点发射/接收硬件延时，p 为空中路径延时：

~~~text
m_AB = T_rx,B − T_tx,A = δt_A + p + δr_B + θ      （B 测量，随 B 的下一个突发发给 A）
m_BA = T_rx,A − T_tx,B = δt_B + p + δr_A − θ      （A 测量，随 A 的下一个突发发给 B）

θ = (m_AB − m_BA)/2 − Δ/2,   Δ = (δt_A + δr_B) − (δt_B + δr_A)
~~~

- 空中路径 p 被消去（同频、同天线位置下认为互易）；
- 非互易常数 Δ 必须通过零基线标定得到（见第 8 节）；
- 一对中的两个突发相隔 2 ms（§5），两个方向经过的空中路径相同；其间两台钟漂移 y × 2 ms（y = 1e-11 时为 0.02 ps），由 ARM 用 Kalman 中的频偏估计扣除；
- `(m_AB + m_BA)/2` 是单程延时，作为诊断量记录。

### 4.3 载波频偏

两个 FS725 的相对频偏在 1e-11 量级，对应 5.8 GHz 下的载波频偏约 0.06 Hz：在一个突发内、以及同一节点相邻两个突发之间的 4 ms 内都可以忽略，所以不需要载波恢复。相关器同时给出包络峰（复相关取幅度，加抛物线插值）和峰处的载波相位；包络用来确定载波的整周数。同一个到达时刻和相位也用于测量包的相干解扩（§5.1）。

## 5. 时隙规划（TDD 乒乓）

两个节点每 2 ms 轮流发射，以本地 PPS 为参考（数值为候选）：

~~~text
时隙 k = 0 … 499 开始于 PPS + k × 2 ms
k 为偶数：A 发射，B 的窗口打开
k 为奇数：B 发射，A 的窗口打开
第 j 对 = 时隙 2j 和 2j + 1：得到一个 θ
~~~

- 一个突发由 PRN（4096 码片，41 µs）、至少一个 RRC 跨度（10 码片）的保护间隔、测量包（§5.1）组成，作为一条码片流一起经过 RRC FIR（P3）；
- 每个突发的测量包带着发送方对上一个时隙（2 ms 之前）对端突发的测量值；
- 为什么是 2 ms：跟踪器在窗口结束后不久就出结果，之后还要组装测量包，传播延时也要放得下（40 km 为 133 µs）；2 ms 又短到一对中两个方向经过的空中路径相同；
- RX 窗口：在预期到达之前打开；窗口长度决定整窗搜索覆盖的延迟范围和搜索所需的时间（现在 43848 个样本：11008 个延迟点，13.8 µs），尚未确定（§10）；窗口送进 PL 相关器（P8），其后的样本送进测量包解码器（P9），只有 ARM 要求时（捕获、核对）才复制一份进 DDR；
- 节点在自身发射期间不开 RX 窗口；
- ARM 只配置一次时隙规划（周期、角色、偏移、预期延时），PL 的时隙引擎（P7）每个时隙自动执行，不需要逐个突发下命令；
- 两个节点从开机起就按时隙开窗，即使对端还没有发射：空窗口锁不上，记为无测量。

### 5.1 测量包

| 字段 | 类型 | 内容 |
| --- | --- | --- |
| 格式版本、`config_id` | u8、u32 | 测量包格式和 RRC 配置（§3.1） |
| `PPS_COUNT`、时隙 | u32、u16 | 发送方这个突发所在的秒和时隙 |
| `TIME_EPOCH` | u8 | 发送方时钟重新锁定时改变：跨越改变的数据不可比 |
| T_tx | i64，距发送方 PPS 的 fs 数 | 这个突发的开始时刻 |
| T_rx | i64，距发送方 PPS 的 fs 数 | 上一个时隙对端突发的到达时刻（P8 跟踪到的峰） |
| 载波相位 | i32，单位 2^-32 圈 | 该峰处的载波相位，即 P8 给出的相位，不再截短 |
| 质量 | u8，单位 0.25 dB | 跟踪器的峰值功率与窗口噪声功率之比（峰旁比要靠整窗搜索才能得到，见 P8） |
| 状态 | u8 | 是否锁定、有无测量、窗口有效、FIFO 溢出、PPS 锁定、时钟锁定 |
| CRC-16 | u16 | |

- 共 36 字节（288 比特）。相位保留 P8 的全部 2^-32 圈分辨率：若只用 16 位（2π/65536，在 5.8 GHz 上为 0.0026 ps），取整会比 P8 的 0.001 ps 验收要求还粗。时间用时间单位表示，不用 tick 数或样本数，这样采样率改变后格式仍然成立；T_rx 不能经过 float32，它在第 1000 个样本附近的分辨率只有约 0.15 ps。
- 调制：100 Mchip/s 扩频的 BPSK，扩频码与 PRN 不同，每比特 L 个码片。L 由链路预算决定，在链路上实测，而不是假设：每比特约 10 dB 的 Eb/N0，CRC 之前的误码率约为 1e-5，而 Eb/N0 = Es/N0 + 10·lg L，Es/N0 是接收端单个码片的信噪比。跟踪器的质量值（§5.1 的表；峰值功率与窗口噪声功率之比）对 4096 码片的 PRN 等于 Es/N0 + 36.1 dB（10·lg 4096），所以它直接给出这条链路上的 Es/N0；L 取能在 10 dB 之上留出余量的最小的 2 的幂，先在有线链路上测（M4b），再在空口上测一次（M6）。在那之前 L = 64，测量包长 0.18 ms（288 × 64 个码片）；P3 和 P9 把 L 作为参数。
- 接收方 PL 用对端上一个突发的到达时刻和载波相位做相干解扩（4 ms 内它们的变化远小于一个码片和 1°），并校验 CRC；校验失败的测量包直接丢弃，不重传。
- PL 把本节点的测量值和解码出的测量包放进队列，ARM 成批读取。
- 配对不需要 NTP：每个节点从每个测量包里学习对端 `PPS_COUNT` 与本地 `PPS_COUNT` 的偏移；偏移改变（漏了一个 PPS 沿）时丢弃那一秒。

### 5.2 初始捕获

- 捕获完成之前，突发使用引导码，即固定的公开码（就是现在的 PRN）。以后的加密码只在两个节点都能解出对方的测量包之后才启用；失去对端的节点退回引导码。
- B 用长窗口（最长约 21 ms）把数据写进 DDR 来听。A 每 4 ms 发一次，一个窗口里就有好几个 A 的突发。ARM 对它做相关、解出 A 的测量包，由 A 的 T_tx 和 `PPS_COUNT` 得到本地 PPS 相对 A 的偏移，误差在未知的传播延时以内。
- B 用 FS725 的 PP 命令（`rf_clock.fs725` 的 `place_pulse()`，1 ns 步长；`rf_clock.pl.acquire.place_pulse_ns`）把 1 pps 输出挪过这个偏移减去修正的目标值（目标值含有 PPS 路径的标定常数，台架上几十 ns）（取整到整 tick），然后开始自己的时隙。取整 tick 是因为 PL 在 tick 上锁存 PPS：按整 tick 移动时 PPS_TICK 正好移动这么多，边沿在 tick 内的位置（它的捕获裕量和 §8 的亚 tick 相位）在 PP 自身的误差以内保持不变；移动零头则会悄悄把这个位置改变若干纳秒。FS725 的 PP 实际移动与指令最多差 0.23 ns（151 ps rms，一串移动下来见过 0.5 ns；2026-11-04 对照设备自己的 10 MHz 测得，`results/m5-v2-20261103/REPORT_zh.md` 第 9.6 节），所以 PPS 常数的标定只在下一次 PP 之前有效。剩下的不到半个 tick 留在 θ 里，由修正去掉（§7.1）。台架已验证（2026-11-03，`results/m5-v2-20261103/REPORT_zh.md` 第 2 节）：11 ms 窗口里有 A 的三个突发，三个包都解出，单程延时已知后，偏移与随后的双向 θ 相差 0.13 ns；ARM 上一次捕获约 25 s。只要 B 的突发落在 A 整窗搜索的延迟范围内，即传播延时已知到该范围的四分之一以内（现在的 13.8 µs 对应约 ±3.4 µs，约 1 km），A 就能找到它；否则 A 也像 B 一样用长窗口搜索。
- 两个方向都测到以后，B 修正 FS725 的频率（§7.1）：同一个环路去掉剩下的偏移（不到半个 tick 加上漂移），然后保持 θ。不用 PP：θ 从锁存 PPS 的那个 tick 算起每个节点的时间（T = P + d，P 是边沿，d 是它在这个 tick 前的提前量），所以修正到目标时 T_B = T_A，两个 PPS 边沿相差 d_A − d_B。调频率时 P_B 和 T_B 一起移动，改不了 d_B；不足一个 tick 的 PP 会在看不见的情况下改变它。整 tick 的移动保住 d_B，d_A − d_B 就是常数，标定一次（§8，PPS 亚 tick 相位）后计入目标值。
- 失去对端后，PL 对窗口做整窗搜索（P8）；只有峰没有移动（±1 个采样以内）、并且强度达到跟踪器保持锁定的要求时，PL 才自己重新入锁，否则由 ARM 先检查单程延时再决定；峰跑出延迟范围时退回长窗口捕获。

### 5.3 一对时隙的时序（P7）

~~~text
        时隙 2j（A 发）                           时隙 2j+1（B 发）                         时隙 2j+2（A）
        |<---------------- 2 ms ---------------->|<---------------- 2 ms ---------------->|
A  发   |-o-|PRN|g|  测量包：2j-1 的 m_BA  |    |                                        |-o-|PRN|g| 测量包：2j+1 的 m_BA |
B  收   |-o-|-d-|[ 窗口：P8 ][ 测量包区段：P9 ]                                           |
B  发   |                                        |-o-|PRN|g|  测量包：2j 的 m_AB    |    |
A  收   |                                        |-o-|-d-|[ 窗口：P8 ][ 测量包区段：P9 ]
                    跟踪器结果 ──> B 的下一个测量包              跟踪器结果 ──> A 的下一个测量包
~~~

| 区间 | 取值 | 由谁决定 |
| --- | --- | --- |
| 时隙 | 200 000 个 tick（2 ms），从 PPS + k × 2 ms 开始，k = 0 … 499 | P7，固定 |
| o：突发在时隙内的起点 | 几 µs，两个节点相同 | P7 寄存器 |
| PRN | 4096 个码片，40.96 µs | P3（码片存储器） |
| g：保护间隔 | 10 个码片，0.1 µs | P3 |
| 测量包 | 288 × L 个码片：L = 64 时 0.18 ms | P3、P9（L 是 RTL 参数） |
| RRC 尾 | 最后一个码片之后 73 个样本 | P3 |
| d：相对对端突发起点的预计到达时间 | 路径加硬件延时 | P7 寄存器，由 ARM 设置 |
| 窗口 | 在预计到达之前 1.25 µs 打开；先取 43848 个样本（54.8 µs），是 RTL 参数 | P7、P8 |
| 测量包区段 | 从窗口结束到测量包最后一个码片，只交给 P9 | P7、P9 |

- B 测量 A 在时隙 2j 的突发（它的窗口和 P8 的跟踪器给出 T_rx 和相位），把这个测量值 m_AB 放进自己在时隙 2j + 1 的测量包；A 对 B 在时隙 2j + 1 的突发也这样做，放进时隙 2j + 2 的测量包。A 解出 B 在时隙 2j + 1 的测量包后，就有了第 j 对（时隙 2j 和 2j + 1）的两半；B 要等解出 A 在时隙 2j + 2 的测量包。
- 每个节点自己的下一个突发在它所测的对端突发之后 2 ms 发出：跟踪器（远少于 0.2 ms）和组包都有充足余量；整窗搜索（2.4 ms）在冻结的窗口上进行，同一节点 4 ms 后的下一个窗口进另一块缓冲区。
- 节点的窗口和测量包区段远早于它自己下一个时隙的突发结束：40 km 的路径延时是 133 µs，窗口、测量包区段和路径加起来不到 0.5 ms。
- 解扩器使用同一对端两个时隙之前（4 ms 前）那个突发的到达时间和载波相位，所以测量包的样本一到就能解；锁定之后的第一个测量包就是第一个能解的。

## 6. PL 模块

所有决定时间的逻辑只在一个时钟域里：RFDC DAC AXIS、ADC AXIS、raw tick、TX buffer 和 RX 时间戳全部运行在同一个由 FS725 派生的 100 MHz fabric 时钟上，打时间戳之前的样本路径没有 CDC。打完 RX 时间戳以后，样本经异步 FIFO 进入 DMA 时钟域，经 P8 的窗口缓冲区进入相关器更快的时钟域（300–350 MHz，同样由 FS725 派生）；两者都不影响计时。AXI 总线通过 BD 中的 clock converter 进入 fabric 时钟域。

### P0 clock_reset：时钟与复位

- 外部 10 MHz → 板上 LMK/LMX → RFDC 参考时钟和 fabric 时钟；
- 监控 PLL lock 和 RFDC 状态，失锁即锁存 FAULT，所有时间戳标记无效；
- 每次重新锁定后递增 `time_epoch`。

### P1 timebase_pps：raw tick 和 PPS 捕获

- 64-bit `raw_tick`，每个 fabric 时钟加一，不在帧边界复位，饱和而不回绕；
- 对 FS725 的 1PPS 输入做同步，捕获 `pps_tick`，统计周期是否正好是 100,000,000 tick，偏差或丢失即报告；
- **注意：** 10 MHz 和 PPS 同源，PPS 沿相对 fabric 时钟的相位每次上电后是固定的，但未知；若恰好落在采样边沿附近，捕获值可能在相邻两个 tick 间跳动。需要检测这种情况（统计 PPS 周期），必要时用 IDELAY 移开。亚 tick 相位属于每次上电都要标定的常数（见 §8）。
- **提议（2026-11-03，尚未实现）：** 用 PPS 输入的过采样副本（在 800 MHz 采样时钟或更快的时钟上用 ISERDES：1.25 ns 或更细）每秒报告 PPS 边沿落在 tick 内的位置，使每个节点都能看到自己的捕获裕量和亚 tick 相位。现在只有能控制自己 FS725 的节点才能找到它们，方法是逐步 PP 直到 PPS_TICK 移动（`rf_clock.checks.pps_pp_scan`；B 的边沿在它的采样沿前 5.33 ns，`results/m5-v2-20261103/REPORT_zh.md` 第 3 节）；另一个节点的边沿临界时，只能从 θ 跳 10 ns 看出来。

### P2 control_regs：AXI-Lite 控制和状态

- 只读：ID/版本、`raw_tick` 原子快照、最近的 `pps_tick` 和 PPS 计数、`time_epoch`、状态、故障位；
- 命令：`TX_TARGET_TICK`、`TX_LENGTH`、`RX_TARGET_TICK`、`RX_LENGTH`，先写 shadow 寄存器，再写 doorbell 原子提交；
- 结果：`tx_actual_tick`、`rx_actual_tick`、完成序号、返回码；
- 拒绝已过期（≤ 当前 tick + 安全余量）的 target_tick、超出 buffer 的长度、在 ARMED/RUNNING 状态下的重复提交；
- 这些单次命令保留给测试使用（M2、M3）；协议由时隙引擎的配置驱动（P7）。

### P3 tx_burst：码片流、RRC FIR 和定时回放

- 码片存储器（BRAM）存放 ARM 写入的固定码（PRN 或引导码、测量包扩频码）；测量包的比特来自 P9；以后的加密码发生器也接入同一条码片流；
- 码片流（PRN、补零的保护间隔、测量包码片）经过多相 RRC FIR（81 个抽头，每码片 8 个样本；码片只有 ±1，只需要加法器），变成 16-bit I/Q beat；
- 测试模式下回放 ARM 预先写入 BRAM/URAM buffer 的样本波形（CW、示波器和频谱测量），和第一版相同，也包括 `TX_REPEAT` 首尾相接的多遍回放，用来发连续信号；它只用于开发测试，经 P2 的单次命令发出，时隙引擎运行时拒绝这些命令；
- 状态：IDLE → ARMED → RUNNING → DONE / FAULT；
- 在 `raw_tick` 等于时隙开始 tick（测试模式下为 `TX_TARGET_TICK`）的那一拍开始，以每时钟一个 beat（8 个复样本）连续输出，直到突发结束；突发之外输出 0；
- ARMED/RUNNING 期间 ARM 写码片或样本存储器 → 报错，不允许修改正在发送的突发；
- 运行中 DAC `tready` 掉落 → FAULT，不暂停、不补发；
- 记录实际开始 tick（应等于 target）。

### P4 rx_capture：RX 定时采集

每个窗口送进相关器的窗口缓冲区（P8）和测量包解码器（P9），ARM 要求时再复制一份进 DDR。窗口与窗口之间不要求连续，但**窗口内部不能丢样本**，两条通路都一样：样本时间按"起始 tick + 样本序号"推算，丢一拍会让后面所有样本的时间错位。

~~~text
ADC AXIS ─> 窗口门控 + 时间戳 ─┬─> P8 窗口缓冲区、P9 解扩
  (100 MHz fabric 时钟域)       └─> 异步 FIFO ─> 位宽转换 ─> AXI DMA S2MM ─> HP 端口 ─> DDR
                                               (DMA 时钟域，例如 250 MHz)
~~~

- 在 `raw_tick == RX_TARGET_TICK` 打开窗口，把 ADC AXIS 的每个 beat 送入 FIFO，数够长度后关闭窗口并给最后一个 beat 打 `TLAST`；
- **时间戳在 ADC 一侧、FIFO 之前记录**：实际开始 tick、beat 数、ADC overflow/over-range 标志。DDR 写入的延迟和抖动不影响时间戳；
- 数据率 800 MS/s × 4 B = 3.2 GB/s。HP 端口为 128 bit，DMA 侧时钟需要 ≥ 200 MHz，并实测与 ARM 同时访问 DDR 时能否持续达到；
- FIFO 只用来吸收 DDR 的短时停顿（几 KB 到几十 KB），不承担缓存整个窗口；
- 提交命令前 ARM 必须已经给 S2MM 准备好足够长的 DDR buffer（PYNQ `allocate`）。DMA 未就绪时 PL 拒绝该命令，不打开窗口；
- **窗口内 FIFO 溢出 → 作废这个窗口**：置 `rx_window_invalid` 并计数，丢弃这次测量；不进入 FAULT，不影响 TX。这一点和 TX 不同：RX 丢一个窗口只是少一次测量；
- DMA 完成后，ARM 先对该 buffer 执行 cache invalidate，再读取样本；
- DDR 通路用于捕获的长窗口（§5.2），以及 ARM 用来核对 P8 的副本；协议中的每个窗口都送进 P8 和 P9。

### P5 rfdc：RFDC IP

- DAC 第二 Nyquist 区 mix-mode、ADC 抽取、NCO 设为 5.8 GHz 相关频点；
- **开启 Multi-Tile Sync（MTS）/SYSREF**，使 DAC/ADC 数字通路延时每次上电都一致；否则标定出来的常数在下次启动后失效；
- RFDC 由 ARM 用 PYNQ `xrfdc` 或 XRFdc 驱动初始化，PL 只提供 IP 和时钟。

### P6 status：状态和故障

- 汇总 P0–P5 和 P7–P9 的故障到一个锁存的状态字，带来源和序号；
- 故障只能由显式 CLEAR 命令或新的 `time_epoch` 清除；
- 第一版用轮询，不用中断。

### P7 slot_engine：乒乓时隙

- 从 PPS 起执行时隙规划（§5）：每个时隙在它的 tick 上启动突发（P3）或打开窗口（P4）；
- ARM 只写一次规划；改动（预期延时、角色、码）在下一个 PPS 生效；
- 来不及按时开始的时隙直接跳过并计数，绝不顺延。

### P8 correlator：每个时隙跟踪，按需搜索

- 两份窗口缓冲区（BRAM，以 800 MS/s 无损写入；长度是 RTL 的参数，现在的 43848 个样本每份约 39 个 BRAM36）：一份继续接收，另一份可以冻结下来给搜索用；
- 参考波形由突发的码片经 RRC FIR 生成，和发出去的完全一致；以后换成加密码也不需要额外步骤；
- 跟踪器：每个窗口只算预测峰位附近的几个延迟点，三点抛物线插值，用 CORDIC 求载波相位；窗口结束后不久出结果，远早于本节点的下一次发射；质量指标为峰值功率与窗口噪声功率之比；
- 整窗搜索：并行的时域相关器，即脉动阵列：参考样本广播给每一路，窗口样本沿移位链流过，每一路算一个延迟点，扫若干遍覆盖全部延迟点；整数乘累加（16 × 16 位，47 位的和放进 DSP48E2 的 48 位累加器），所以相关结果与 ARM 的 float64 完全一致；11008 个延迟点 × 32841 个样本约 7.2 亿次乘法：300 MHz 下 1024 个 DSP 用 2.4 ms，2048 个用 1.2 ms（器件共 4272 个，跟踪器约用 150 个）；
- 跟踪器没有锁定（失锁，或开机后还没锁上；此后每来一个新窗口就再搜一次，直到锁定）或 ARM 请求时启动搜索；锁定期间 ARM 会不时请求一次，以便发现锁到了错误的峰（被延后的副本、多径）；同一时刻只做一次搜索（busy），忙时的请求拒绝并计数；
- 搜索结果附上该窗口的 `PPS_COUNT`、时隙号和起始 tick，报告：最强峰、不比最强峰低过设定门限的峰里最早的那一个（直达路径最先到）、峰旁比、窗口状态；
- 重新入锁：只有新峰离旧峰在 ±1 个采样以内、并且幅度通过跟踪器对上次锁定的幅度检验时，PL 才自己接上（2026-11-03 台架上，一个碰巧落在旧延迟点附近的噪声峰曾被锁上）；否则由 ARM 先检查单程延时再决定；未锁定的时隙，测量值标记为无效；锁定期间 ARM 请求的搜索不影响跟踪器测量值的有效性；峰跑出延迟范围时交给 ARM 用长窗口捕获；
- 时钟：第一版 RTL（rf-clock 2.0）的搜索运行在 100 MHz 的 fabric 时钟上，1024 条通道（2048 个 DSP），每次约 3.9 ms，这样不需要跨时钟域；若时序允许，改用由 FS725 派生的 300 MHz 时钟可以用一半的 DSP 做同样的事；
- 估计算法必须与 ARM 上的相同（`rf_clock.correlator.estimate_delay`），这样标定常数才能沿用；以同一窗口上 ARM 的 float64 结果为准验收：包络差 0.01 ps 以内，相位差 0.001 ps 以内；
- 结果（窗口 tick、峰位、亚采样位置、相位、质量）送给 P9 和测量队列；
- 研究过的另一方案是每个窗口都做 65536 点 FFT 相关（2026-11-01：约 550–620 个 BRAM36、250 个 DSP，每个窗口 0.7–0.9 ms，数据 27 位、旋转因子 18 位时精度足够）；时域搜索不需要参考谱，存储占用小，而且只在需要时运行。

### P9 packet：测量包

- 用 P8 的最新结果、本时隙的 T_tx 和状态组装 §5.1 的测量包，加上 CRC，把比特交给 P3，由 P3 用测量包扩频码扩频后接在 PRN 后面；
- 在每个窗口里相干解扩对端的测量包（§5.1），校验 CRC，把解出的字段放进队列；
- 队列至少能放下一秒内两个节点的测量值，ARM 成批读取。

### P10 pps_out：输出 PPS（2.1 起）

给其他设备用的节点 PPS，由节点的时间尺度产生，而不是取 FS725 的 1PPS（设计和理由见 `plan/pps_output_zh.md`）：

```text
FS725 1PPS ──> P1：PPS_TICK(k) ──> P10：相位计数器（由锁定的边沿对齐，两个边沿之间靠飞轮）
                                     │ 在 PPS_TICK(k) + OFFSET：DAC tile 0 数据流上的一个阶跃
                                     v
                     DAC tile 0（基带，旁路混频器）──> 100 nF ──> 巴伦 ──> 100 nF ──> J20（DAC_B）
                     有效状态线 ──> NVT2008BQ ──> Pmod J1 第 1 针（高 = 无效）；LED W_LED_0
```

- 从开始这一秒的那个锁定边沿的 PPS_TICK 起数这一秒的 tick，边沿缺失时自己接着数（飞轮，计数）；
- 每一秒里，在 PPS_TICK + OFFSET 送出的那一拍从第 SAMPLE 个采样起（以 1.25 ns 为步长）带一个阶跃，共 WIDTH 拍，阶跃从空闲电平 IDLE 起跳（2.2 起；IDLE = −AMPLITUDE 时阶跃加倍）；J20 上的边沿在秒的起点 + OFFSET × 10 ns + SAMPLE × 1.25 ns + D_board（§8）；它的上升时间 0.95 ns 由 tile 0 每秒 8 亿采样的数据流决定，而提高这个数据率就会失去 tile 2 的 MTS（IP 只在内插倍数相同时保留 DAC tile 的 MTS；`results/pps-out-20261104/REPORT_zh.md` 第 9 节）；
- 输出跟随 θ 对齐的时间尺度，所以 PP 的误差和 FS725 1PPS 的抖动都进不去，定时由 DAC 的采样时钟给出；
- 有效状态线为高，除非 PPS 输入和时钟都已锁定、这一秒由锁定的边沿开始、DAC 接收数据流、并且 ARM 已表示时间尺度已同步；没有 bitstream 时也为高（电平转换器的上拉）；
- 寄存器见 `docs/ABI_zh.md` §4.13；仿真 `PL/sim/tb_p10_pps_out.v`。

### 6.1 第一版不需要的东西

- **TX 不从 DDR 流式读取**：突发由片上数据生成（P3），连续性靠结构保证；只有 RX 使用 S2MM DMA；
- PL 内的 DSP 只限于每个突发的链路（P3 的 FIR、P8、P9）；
- 不需要 scatter-gather DMA 和中断：每个窗口一次 simple 模式传输，用轮询等待完成。

### 7.1 FS725 修正策略

- 只有 B 被修正；A 自由运行；
- 第一版只通过 RS-232 调整 B 的频率偏移：频率误差直接修正，PPS 相位误差通过临时增加频偏、让相位逐渐滑过去来修正；
- 修正命令是 SF（PRS10 手册）：频率偏移，单位 1e-12，−2000 到 +2000，相对 EEPROM 里的校准值。第一次发 SF 后校准电位器失效，设备锁相到 1 pps 输入时 SF 被忽略，所以修正要从 SF? 读到的值开始，并关掉那个锁相（`rf_clock.fs725`）。在 B 那台上实测（2026-11-03，`results/m5-v2-20261103/REPORT_zh.md` 第 5 节）：SF +100 在一两秒内让 θ 的变化率增加 101.5 ps/s；SF 背后的磁场 DAC 一步是 3.4 个 SF 单位，所以更细的 SF 只能在平均意义上实现；
- 环路时间常数取数十到数百秒，与铷钟本身的稳定度相匹配。在白调频噪声下 θ 的残差约为 σ_y(1 s)·√(τ/2)，所以 FS725 的响应允许的最短 τ 最好；`rf_clock.twtt.steer` 默认 50 s（`experiments/m5_steer_sim.py`）。台架上的两台 FS725 经 θ 和示波器实测（2026-11-03，报告第 4 节）：Allan 偏差 1 s 时 1.4 × 10⁻¹¹，之后大致按 τ^−0.8 下降，256 s 时 4.3 × 10⁻¹³；两台钟的相对频率还有一个周期约 5.3 s 的振荡；θ 绕直线游走约 70 ps rms，大部分在几十秒的尺度上。把这段记录回放进环路，τ = 50 s、每 10 s 修正一次为 55 ps rms，τ = 5 s、每 2 s 一次为 33 ps，τ = 2 s、每秒一次为 25 ps；台架上前者把 θ 保持在 66 ps rms，后者 39 ps（报告第 6 节）。回放时加上 FS725 1.9 s 的响应延迟，5 s、每 2 s 一次为 42 ps，再快也不会更好（2 s、每秒一次为 63 ps）：这对钟的下限约 40 ps（1.9 s 里 FS725 自己的 1.1-1.6 s 约占 15 ps：θ 改取每秒最后 0.2 s 而不是整秒为 38.5 ps，FS725 若瞬时起作用为 25 ps；报告第 6.5 节）；
- rf-clock 2 里由节点自己修正自己的 FS725：`rf_clock.checks.m4c_link --steer-target-ns` 把每秒的 θ（来自 B 自己的测量队列）交给 `rf_clock.twtt.steer`，经 B 的 USB 转 RS-232 适配器设置 SF；
- FS725 的频率在 SF 命令之后约 1.1-1.6 s 才跟上，所以滤波器从发起它的那一秒之后 1.9 s 起才计入 SF 的改变，并在改变刚发生时放宽剔除门限；否则快速环路（τ = 5 s）的第一个大阶跃会让滤波器连续剔除十个 θ 并重新开始，台架上就发生过（2026-11-03）。开始时误差大，SF 就停在允许范围的边上追赶，而不是停止修正；只有控制律连续两分钟要求超出范围才会停止。

## 8. 标定

| 量 | 方法 | 何时重做 |
| --- | --- | --- |
| 非互易常数 Δ | 零基线：两个节点共用同一台 FS725 的 10 MHz 和 PPS（PPS 分配线缆长度已知），此时真实 θ 已知，由 (m_AB − m_BA)/2 = θ + Δ/2 解出 Δ | 更换线缆、放大器、滤波器、天线或 RFDC 配置后 |
| PPS 相对 fabric 时钟的亚 tick 相位 | 示波器/时间间隔计数器，或把 PPS 接入一个空闲 ADC 通道，在 GS/s 级时间分辨率下测量；能控制自己 FS725 的节点可以用 PP 以 1 ns 步进，直到 PPS_TICK 移动（`rf_clock.checks.pps_pp_scan`：边沿比它的采样沿早多少，精确到 1 ns；2026-11-03） | 每次上电（除非证明板上 PLL 相位确定） |
| RFDC 通路延时 | 本板 DAC→衰减器→ADC 有线环回，多次重启后比较 | 修改 RFDC 配置后；用来验证 MTS 生效 |
| 输出 PPS 的延时 D_board（P10） | 示波器上 J20 的边沿相对节点 FS725 的 1PPS，减去 OFFSET × 10 ns + SAMPLE × 1.25 ns 和 PPS 捕获裕量（第 2 行）；多次上电后比较 | 修改 RFDC 配置或 DAC_B 通路后 |

标定值存储在软件中，必须带版本号；绝不能在代码里减一个凭感觉猜出来的常数。

## 9. 实施顺序和验收

| 阶段 | 内容 | 验收 |
| --- | --- | --- |
| M0 | FS725 10 MHz 接入板上时钟链，PPS 接入 PL 管脚 | 板上 PLL 锁定在外部参考；RFDC 时钟正确 |
| M1 | P0/P1/P2 | ARM 读到每秒正好 100,000,000 tick；拔掉参考时报 FAULT |
| M2 | P3 + P5，示波器以 PPS 触发观察 DAC 输出 | 突发相对 PPS 的延时固定；多次重启后不变（MTS 生效） |
| M3 | P4，本板 DAC→ADC 有线环回，ARM 做相关 | 环回延时测量的标准差和重启后的一致性；S2MM 在 ARM 同时访问 DDR 时持续写入不溢出 |
| M4 | 两块板，有线连接加衰减器，共用一台 FS725 | 零基线测得 Δ；θ̂ 的噪声水平 |
| M4b | P7–P9 和 P3 的 FIR，先在 M3 回环上，再在有线连接的两块板上 | P8 与同一窗口上 ARM 的 float64 结果一致（包络 0.01 ps 以内，相位 0.001 ps 以内）；长时间运行中测量包都能解出并通过 CRC；带与不带测量包时 θ 和回环延时不变；不用 NTP、按 `PPS_COUNT` 配对；失锁触发和 ARM 请求的搜索，以及 P8 的重新入锁规则 |
| M5 | 各用自己的 FS725，有线连接，完成捕获（§5.2），闭合 Kalman + FS725 修正环路 | 用时间间隔计数器测量 PPS_A − PPS_B，长期收敛；2.1 起节点的 PPS 是输出 PPS（P10），它们的差还必须在多次重新捕获和上电之后保持不变 |
| M6 | 换成 5.8 GHz BPF、放大器、天线的空中链路 | 与 M5 相同的指标，记录多径和 SNR 的影响 |

每一项证据都要注明来自仿真、综合、板上测量中的哪一种。最终指标是外部时间间隔计数器测得的 PPS_A − PPS_B，而不是系统自己报告的 θ̂。

## 10. 待确认项

逐项进度和依据记录在 `plan/checklist_zh.md`。

1. **板卡型号和外部参考输入**：板上时钟链能否接受 10 MHz 外部参考，RFDC 和 fabric 时钟能否都从它派生？
2. **天线**：TX/RX 分开天线，还是共用一副天线加 T/R 开关（若共用，PL 需要在 target_tick 输出开关控制，并保护 LNA）？
3. **测量包**：测量值随突发传送（§5.1）。待定：按 §5.1 的方法实测确定的扩频因子 L（在那之前 L = 64；2026-11-03 在电缆连接的两块板上，发射幅度 16000 时跟踪器的质量值为 45.25 dB，Es/N0 ≈ 9.2 dB，所以 L = 64 给出 Eb/N0 ≈ 27 dB；幅度降到 4000 时每个包仍然都能解出：按 §5.1 的规则那里 L = 8 就够，但这个 SNR 是衰减器定的，所以在空中链路 M6 之前 L 保持 64），以及测量包的字段和寄存器（只新增寄存器时 `VERSION` 主版本号不变；改动已有寄存器则主版本号加一，见 `docs/ABI.md` §14）。
4. **FS725 的 PPS 粗对齐**：PRS10 能用 PP 以 1 ns 步长移动 1 pps 输出；§5.2 用它配合 RF 捕获测出的偏移来对齐（`place_pulse()`），按整 tick 移动；2026-11-03 在台架上验证（10 步 PP 正好一个 tick，实测 9.90 ns）。一次 PP 的实际移动与指令最多差 0.23 ns，1PPS 本身相对设备的 10 MHz 有 22-34 ps 的抖动（2026-11-04）。**2.1 起**节点的输出 PPS 由 PL 从它的 tick 产生（P10，`plan/pps_output_zh.md`）：DAC_B（J20）上的一个脉冲，在 PPS_TICK 之后一个可设定的延时。它跟随 θ 对齐的时间尺度，中间没有 PP，也没有 FS725 PPS 的抖动；FS725 的 1PPS 只作为 PPS 输入。从 tick 到 J20 的延时是一个板级常数，标定一次即可（§8）。在 B 板上（2026-11-04，`results/pps-out-20261104/REPORT_zh.md`）它相对 B 的 10 MHz 稳定在示波器每秒 7 ps 的分辨率以内，经过十次 PP 移动正好按整 tick 移动（3.1 ps rms），而 1PPS 每次差 40-260 ps；六次 PL.open 后在 8.7 ps 以内。修正 B 时把两块板的输出 PPS 都接到示波器上，经过一次带 PP 的重新捕获和两块板的 PL.open，它们的差保持在 0.9 ps 以内（报告第 8 节），而 FS725 的 1PPS 丢了 145 ps；断电重启还没有做。把对端的 PPS 接到后面板 1 pps 输入上打时间标签（TT?，1 ns，`rf_clock.fs725 align`）仍可作为台架上的备选方法。
5. **目标精度**：ns 级可以用码相关完成；若需要 100 ps 甚至更好，需要加入载波相位测量，并更严格地处理 PPS 亚 tick 相位。
6. **法规**：5.8 GHz 发射功率和占用带宽限制。
7. **安全**：监视单程延时；Kalman 滤波的新息门限；最早峰的门限（P8）；测量包上的消息认证码；加密码（§5.2）及其密钥。
8. **雨中的极化**：两个方向用正交极化时，雨滴造成的极化间相位差会让链路不互易（估计 40 km 大雨时为 10–20 ps，未实测）；两个方向用同一个极化可以避免。
9. **RX 窗口长度**：现在的 43848 个样本对应 11008 个延迟点（13.8 µs），1024 个 DSP 搜索一次 2.4 ms；窗口越长，搜索和 A 第一次接住 B（§5.2）能覆盖的范围越宽，搜索时间也按比例变长。窗口长度是 RTL 的参数。它先取 43848 个样本，这个值不是本设计推出来的，而是 M3/M4 节点用的窗口（突发本身的 32841 个样本，加上预计到达之前 1.25 µs、之后 10 µs），沿用它是为了让 M4 存下的 RX 窗口能直接当测试向量。最终取值由链路距离知道得多准（A 第一次接住 B 要求延时误差在延迟范围的四分之一以内）和直达峰之后的多径延续多远决定。
