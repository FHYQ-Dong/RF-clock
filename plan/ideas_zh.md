# RF-clock 想法

英文版 `plan/ideas.md` 为准，本文是它的中文翻译。

尚未排期、也未验证的想法。每条写明问题、逐环的机制（哪一环是实测、哪一环是推断）、怎样验证、代价是什么。它们来自 2026-10-26 把 RF-clock 和量子双向时间传递（Q-TWTT，参考文献见文末）做的对比。没有一条触及 `AGENTS.md` 里的架构约束。

最后更新：2026-10-26

## 1. 经环行器共用一条路径，并均衡带通滤波器

### 问题

M4 接线中每个方向各有自己的电缆、带通滤波器（Mini-Circuits ZVBP-5800-S+）和衰减器：887329260072A 到 887329260101 是 10 dB，反方向是 20 dB。

1. 每个滤波器按自己的群延时推迟 burst：在 burst 频带（5.8 GHz ± 62.5 MHz）内为 3.53–4.11 ns，峰峰值 586 ps，向带边上翘（Mini-Circuits 典型器件 S 参数，`results/bpf-compare-20261022`；我们手上的两只没有实测）。
2. 每个滤波器只在一个方向上，它的延时只进入那个方向的单向测量 m_AB 或 m_BA，于是两只滤波器之差以一半进入 theta = (m_AB − m_BA)/2：恒定的差是非互易 Δ 的一部分，标定之后的任何变化都会移动 theta（由 `src/rf_clock/twtt/timing.py` 的双向方程得出）。
3. 包络计时跟随按 burst 频谱加权的群延时，载波计时跟随 5.8 GHz 处的相位，所以滤波器的响应平移或变形时两者移动的量不同（用 S 参数仿真：整个响应平移 1 MHz，包络相对载波移动 1.9 ps）。
4. M4 中包络相对载波一夜最多移动 41 ps，断电重启之间移动 +37 到 +59 ps，载波只移动几 ps（实测，`results/m4-twtt-20261021`）。滤波器的典型温度系数（包络相对载波 0.25–0.29 ps/K）远不够解释这么大的移动（按典型器件推断）；原因未明。

Q-TWTT 让两个方向走同一根光纤，两端各用一个光环行器把收发分开，所以光纤的延时及其变化对两个方向是共同的。

### 1a. 共用路径

接线：每块板用一个环行器把 DAC_A（端口 1 → 2）和 ADC_B（端口 2 → 3）合到它的端口 2 上；两块板的端口 2 之间只用一根电缆、一个带通滤波器和一个衰减器连起来。

1. 滤波器、电缆和衰减器都是无源线性器件，因而互易（S21 = S12）：burst 在两个方向上经历相同的群延时和相同的纹波（物理规律；我们这几只器件的互易性没有实测）。
2. 于是共用部分给 m_AB 和 m_BA 加上相同的延时：它在 theta 中抵消，只出现在单向延时 (m_AB + m_BA)/2 里，随温度的变化也一样。
3. 剩下的非互易都在每块板本地：DAC_A 到端口 1、环行器的端口 1 → 2 和端口 2 → 3、端口 3 到 ADC_B。它和现在转换器的延时一样归入 Δ，温度依赖可以逐块板测量。
4. 共用部分里还留一个残差：滤波器两端看到的负载不同（各板的端口 2，其后 DAC 和 ADC 的失配经环行器有限的隔离漏过来），所以滤波器与两端之间的反射在两个方向上不一定相同（推断；大小未知）。

可行性：

- 时隙是分时的：A 在 PPS 沿后 100 ms 发射，B 在 600 ms（`src/rf_clock/twtt/timing.py` 的 `SLOTS`）。一块板发射时从不接收，所以环行器有限的隔离（典型约 20 dB）只会让本板的 burst 在本板 ADC 不采集的时候进入 ADC。要核对这个电平不超过 ADC 的最大输入。
- 两个方向这时共用一个衰减器、损耗相同；选它使两边的 ADC 电平都合适。
- 用二路功分器（Wilkinson 或电阻式）代替环行器同样互易，而且宽带。每端 3–6 dB 的损耗在链路本来就要衰减（现在 10–20 dB）时不算代价；但电阻式功分器的 DAC 与 ADC 之间只有约 6 dB 隔离。
- 硬件：两个 5.8 GHz 环行器（或功分器），滤波器从两只减为一只。

验证：在共用路径上跑 M4，然后加热滤波器（热风枪或用手）。预测：现在的接线下，被加热方向的包络移动，theta 跟着移动；共用路径上，单向延时移动而 theta 不动。之后在零基线上重新标定 Δ。

### 1b. 在 ARM 上均衡滤波器的形状

Q-TWTT 里对应的是非局域色散消除：在本地（idler）一路放一段色散补偿光纤，在符合测量中抵消远端光子经历的色散。它使相关峰变窄，但不去掉群延时本身；而且在 103 km 实验里，补偿光纤本身就是不确定度预算中 9.1 ps 的一项非互易。相干接收机不需要第二段光纤：同样的事可以在 ARM 上的相关里做。

1. 从保存的 RX 窗口估计每个方向的信道响应 H(f)（`experiments/m4_channel.py` 现在就能做）。
2. 用经过 H 的非线性相位部分的 PRN 模板做相关，或者在相关之前从接收频谱中去掉这部分相位。
3. 这样滤波器的形状不再把包络拉离载波（推断；要在保存的窗口上验证）。

它做不到的：H 的线性相位部分是纯延时，单个方向分不清它和钟差，所以滤波器延时的漂移仍留在 m 里（配合 1a 的共用路径时在 theta 中抵消）。固定的 H 在滤波器变化后就过时了；跟踪的 H 只能跟上它的形状。它也是让想法 2 不把滤波器变成计时噪声的办法（见该节）。

验证：先离线做，用 `rf_clock.twtt.node --save-every` 保存的窗口：比较一夜中均衡前后包络减载波的变化。

从源头去掉问题的另一条路：换群延时平坦的滤波器（VBFZ-5500-S+，典型数据下全带内约 2 ps），但需要在 3.8 GHz 处补抑制（做到 1 ps 需比 5.8 GHz 信号低约 63 dB；`results/bpf-compare-20261022`）。

## 2. 每秒由共享密钥派生新码

### 问题

burst 每次都一样：由固定 LFSR 种子生成的 4096 码片 BPSK（`src/rf_clock/pl/waveform.py` 的 `DEFAULT_LFSR_SEED` = 0xACE1），节点启动时写入 TX 缓冲一次（`src/rf_clock/twtt/node.py` 的 `run_node`），在 PPS 沿后的固定 tick 发出。知道码和时间表的人可以在真 burst 到达之前合成一个。对射频路径的攻击，双向测量能看到什么、看不到什么：

1. 攻击者让 AB 的 burst 晚到 δ_AB（为负则早到）、BA 的晚到 δ_BA，theta 变化 (δ_AB − δ_BA)/2，单向延时变化 (δ_AB + δ_BA)/2（双向方程）。
2. 把单向延时和它的标定值比较，能发现两者之和的任何变化，但发现不了 δ_AB = −δ_BA：一个方向推迟、另一个方向提前同样多，theta 移动 δ_AB，延时不变。
3. 让 burst 提前，需要在它到达之前就拿到它。码已知时可以做到：合成它，在真 burst 到达之前以更强的功率发出。码无法预测时做不到：码只有收到后才知道，转发要花时间。
4. 只能推迟时（δ_AB、δ_BA ≥ 0），theta 的变化不超过延时的变化，所以容差为 ε 的延时检查把未被发现的 theta 误差限制在 ε 以内。不可预测的码和延时检查只有放在一起才起作用（Narula 和 Humphreys 2018：测量往返是安全时钟同步的必要条件，但不充分）。
5. 还要一个条件：合法路径必须最快。攻击者在一块板附近接收、经更快的路线转发，就能把差值变成提前量（空气中的直线比约 0.7 c 的同轴电缆快）。视距无线电满足这一条，台面上的电缆不满足。

Q-TWTT 的第 3 环来自物理：光子对在随机时刻产生，没人能在光子产生之前发出它。它仍然需要第 4 环（Lee 等 2019 的非对称延时攻击对它同样有效）和经过认证的数据交换（想法 3）。

### 想法

- 两块板共享一个秘密，放在只有 root 可读、不在包里也不在仓库里的文件中，和板级配置一样，但按板对而不是按板。不同用途从它派生不同的密钥（例如用 HKDF）：这里是 K_code，想法 3 用 K_link。
- 每一秒、每个时隙的码片取 K_code 下 AES-CTR 以 (秒, 时隙) 为 nonce 的前 4096 比特。"秒"必须是两块板不用通信就能一致的数：现在配对记录的方法（PPS 沿的系统时间，NTP 在毫秒以内，`PAIR_TOLERANCE_S`）就能给它命名，例如 PPS 沿系统时间取整。同一密钥下 nonce 绝不能重复。如果两块板不一致，相关找不到峰：丢一秒，而不是错的时间。
- 发射端：ARM 在当前一秒最后一个时隙之后算出下一秒的 burst，在武装之前写入 TX 缓冲（TX burst 仍预载入片上缓冲）。
- 接收端：ARM 生成同一秒的参考来做相关。
- 第 4 环的延时检查：把 `delay_ns` 和它的标定值比较，超出容差时给这一秒打标记（不进 `FAULT`）。容差能多紧，取决于单向延时自己漂多少。

代价和风险：

- 依赖于码的偏差：经过有群延时纹波的滤波器，计时取决于码的频谱。固定一个码时这个误差是常数，归入 Δ；每秒换码后它变成噪声。对 ZVBP-5800-S+ 的粗估：每个 burst 1–2 ps（586 ps 的纹波在随机 41 µs 码约 5000 个独立频点上平均；没有仿真）。均衡（1b）或平坦的滤波器可以去掉它；只有共用路径（1a）不行，因为两个方向这时用的是不同的码。
- 旁瓣：每个码有自己的相关旁瓣；随机 4096 码片的最高旁瓣约 −24 dB（粗估）。要核对 `psl_db` 始终远高于 `MIN_PSL_DB`。
- 每秒的 ARM 时间：生成并成形两个 burst、把一个写入 TX 缓冲（待测）。
- 安全性是计算安全，不是信息论安全。对授时这一点关系不大：攻击必须实时进行，事后破解密钥一无所获。如果两站之间有 QKD 链路，用它的密钥可以让码成为一次一密。

验证：M4 中逐秒交替使用固定码和密钥派生的码，比较两者 theta 的均值和离散。

## 3. 认证交换的记录（HMAC）

### 问题

两块板通过明文 TCP 交换记录（端口 50725 上的 JSON 行，`src/rf_clock/twtt/link.py`）。记录里有计算 theta 所需的一切：发射 tick、接收 tick、相关峰位置和相位。两块板之间网络上的任何人都可以改它们：把 B 报告的 AB 时隙接收时刻加 x ns，两块板上的 theta 都移动 x/2，完全不用碰射频。想法 1 和 2 只保护射频路径。

### 想法

- 每条消息附一个标签：用 K_link（密钥见想法 2）对消息的原始字节计算 HMAC-SHA256。
- 接收方重新计算标签（用 `hmac.compare_digest` 比较），标签不符的消息丢弃并记入日志。
- 重放：录下的真消息仍然有效，所以被签名的字节里要包含一个必须递增的数，例如记录的 PPS 计数，加上每次连接时双方在 `hello` 里发的随机数；旧消息丢弃。
- HMAC 提供完整性和真实性，不提供保密；记录也不需要保密。
- 另一种做法：在 socket 外包一层带证书的 TLS。板上的 Python 3.10 支持（预共享密钥的 TLS 要 Python 3.13）。设置更多，在这里效果相同。

验证：`tests/` 里的单元测试（改过的消息、重放的消息、错误的密钥），然后带标签跑一次 M4。
